## 3. 分析参数

- Sheet3 提取：`load_workbook(data_only=True)`，逐行逐列输出非空单元格并记录 `column_letter`、列头、`merged_cells.ranges`；对每行计算 `filledCols` 与 `missingCols`。
- 派生比对：按「指南原词」列做键匹配；比较前归一化（`re.sub(r"\s+", "", s)` 去空白，全角 `（）；，：、` 转半角）；逐字段比较 9 个文本字段，另将「分析方法（首选）」「正交/补充方法」与站点 `methods[].rawSourceText` 去重后以「；」连接比较。
- 机械校验：`verify_similarity_schemes.mjs` 用正则切分 scheme 块（以 4 空格缩进的 `itemId:` 为分隔），不执行 TypeScript；工作簿 SHA-256 用 `node:crypto` 实时重算。

## 5. 输出摘要

### 5.1 派生比对：一级结构区零差异

| 指标 | 结果 |
|---|---|
| V2 Sheet2 一级结构行（row 2–14） | 13 |
| 匹配到站点项目 | **11** |
| 未匹配（均为 `示例占位项`，属 PTM 大类） | 2（row 9 修饰1、row 10 修饰2） |
| 站点项目在 V2 中无对应行 | **0** |
| **字段级差异总数** | **0** |

**这修正了 P0 的一处推断错误**：P0 曾把「V2 一级结构 13 行 vs 站点 11 项」记为潜在分叉风险，实际是 2 个 PTM 占位行造成的计数差，内容上没有任何分叉。

### 5.2 Sheet3 规则清单

Sheet3 共 14 列 × 12 行（row 12 全空），10 个非空数据行。规则内容列为 G–N 八列。

**完整规则 7 条，治理 21 条方法：**

| row | 指南原词 | itemId | 方法数 | 判定规则类型 |
|---|---|---|---|---|
| 2 | 完整分子量 | `intact-mass` | 3 | 2.1 + 2.2 |
| 3 | 脱糖分子量 | `deglycosylated-intact-mass` | 3 | 2.1（主要）+ 2.2 |
| 4 | 轻链分子量 | `light-chain-mass` | 3 | 2.1 + 2.2 |
| 5 | 非脱糖重链分子量 | `non-deglycosylated-heavy-chain-mass` | 3 | 2.1 + 2.2 |
| 6 | 脱糖后重链分子量 | `deglycosylated-heavy-chain-mass` | 3 | 2.1 + 2.2 |
| 7 | 序列覆盖率/一级质谱 | `ms1-sequence-coverage` | 3 | 2.1 |
| 8 | 序列覆盖率/二级质谱 | `msms-sequence-coverage` | 3 | 2.1 |

**空缺 4 项 → `RULE_NOT_DEFINED`，治理 0 条方法：**

| Sheet3 状态 | itemId | completeness | 缺失列 |
|---|---|---|---|
| row 11 存在但不完整 | `cdr-signature-peptides` | `partial` | A、**G–N** |
| 无对应行 | `n-c-terminal-sequence` | `absent` | 全部 |
| 无对应行 | `free-thiol` | `absent` | 全部 |
| 无对应行 | `disulfide-bonds` | `absent` | 全部 |

**无法映射的 2 行**：row 9/10「翻译后修饰—修饰1/修饰2」，属 PTM 大类且为未命名占位项，无法分配 itemId，故不写入 `similaritySchemes`（避免发明 id），单独导出为 `unmappedSheet3Rows`。

### 5.3 源工作簿的数据质量问题（逐条实测）

| 问题 | 位置 |
|---|---|
| 列错位：本应在 A 列的「示例原项」被填入 B 列，挤掉 CTD 章节 | row 5、6、7 |
| A、B 皆空（B 由合并区 `B7:B8` 覆盖） | row 8 |
| 笔误「还原+酶法脱糖**后后**LC-ESI-MS」 | row 6 E 列（已逐字保留并加注释） |
| 合并单元格 | `B7:B8`、`B11:B12`、`D9:D10` |

这些错位正是 `similarity-schemes.ts` 采用**手工维护而非通用行读取器生成**的理由：通用读取器会把错位的「示例原项」当作 CTD 章节静默吞下。所有缺失列已逐条记入 `provenance.missingCells`。

### 5.4 数值边界的一致口径

五条质量规则（row 2–6）K 列**逐字相同**：「无统一相似性数值限度；实测质量与理论质量偏差应符合方法特异预设的质量准确度标准」。
两条覆盖率规则（row 7/8）K 列：「无序列覆盖率的统一合格判定阈值……尽可能实现完整覆盖」。

**七条规则无一提供可比较的数值阈值。** 界面不得把 ΔDa / Δppm / 覆盖率百分比渲染成合格线。

M 列依据存在差异：质量类引用 CDE 2026 + FDA 2025 + WHO 2022 + ICH Q6B + **ICH Q2(R2)**；覆盖率类不引用 ICH Q2(R2)，与其「无统一阈值、以覆盖充分性论证为主」的定位自洽。

```text
npx tsc --noEmit                          → exit 0
node scripts/verify_similarity_schemes.mjs → exit 0

V2 similarity scheme check
--------------------------
primary-structure items      : 11
schemes declared             : 11
  by completeness            : {"complete":7,"partial":1,"absent":3}
programmable (complete)      : 7
methods governed by a rule   : 21
source workbook SHA-256      : matches
warnings                     : 0
failures                     : 0

npm run check                             → exit 0，全绿
  typecheck / lint / verify:cases / verify:demo /
  verify:method-content (184 方法 / 33 有正文, failures 0) / verify:schemes
```

`verify:schemes` 的七项强制检查中，第 5 项最关键：**非 `complete` 的 scheme 不得携带任何规则字段，`methodIds` 必须为空**。这把「不得从 Sheet2 补造规则」从一条纪律变成了结构约束——任何人往 `cdr-signature-peptides` 加一个 `decisionMethod`，`npm run check` 会立即失败。

第 7 项检查用 `node:crypto` 实时重算工作簿 SHA-256 并与代码中记录的值比对，源头被静默改动会被捕获。

## 7. 局限性

1. **V0.1 工作簿丢失** → `characterization-items.ts` 与 `regulatory-framework.ts` 已无法再生成，`scripts/generate_data.py`（第 24 行硬编码 V0.1 绝对路径）处于不可运行状态。这使 D4「只建 sidecar」从优选变为唯一可行方案。建议作为独立后续任务处理，本计划不做迁移。
2. **本步的 V0.1↔V2 比对是派生比对**，不是原始工作簿对比。结论「零差异」的准确含义是：V2 Sheet2 与 V0.1 生成物的文本一致，无法排除 V0.1 原始工作簿中存在未被生成脚本读取的字段。
3. **SHA-256 校验无法防止「改动后 SHA 一并更新而语义变了」**。规则文本的科学正确性与解读正确性仍需人工复核，机械校验只覆盖 id 链接与结构完整性。
4. **规则治理率仅 64%**（21/33 方法）。P11 界面必须让有规则与无规则一眼可辨。
5. **英文为机器翻译占位**，与站点既有约定（`characterization-items.ts` 头部同样声明）一致，未经专业校对。
6. **游离巯基最易被误用**：Sheet2 row 13 确实写明了 `QR = (μR − XσR, μR + XσR)` 与「90% 以上批次落入」，但 Sheet3 未编写为程序规则。按 D2 系统只算不判。
