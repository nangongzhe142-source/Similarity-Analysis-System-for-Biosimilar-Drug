## 一、契约范围

## 二、相较原九节 spec 的四处增补

| 字段 | 原因 |
|---|---|
| `provenance` | P12 溯源面板参照 `LiveDemoProvenance`；D20 要求在结果 JSON 内可下载、可审计 |
| `inputEvidence.samplePairing` + `isHeadToHeadBiosimilarDesign` | D20：任意两侧可比对，但公开 fixture 不得暗示头对头生物类似药设计 |
| `extractedFeatures.coverageDefinition` + `coveragePercentByDefinition` | DOCX 图 6 五种覆盖率口径；裸百分比会被误读 |
| `evidence.parameters.massConstantSource` | P1：pyOpenMS 与 ExPASy 平均残基质量在 148 kDa mAb 上差 ~9 ppm，必须记入参数 |

原 spec 的 `evidence`（运行元数据）保留；新增的 `provenance`（面向读者的溯源叙述）与其分工不同，不合并。

## 三、三端一致性机制

```
src/types/analysis-contract.ts
        ↕  verify:analysis-contract（wire 字段名 + requiredness）
analysis-service/contracts/field-manifest.json  ← export_contract_schema.py 从 Pydantic 导出
        ↕
analysis-service/contracts/analysis-result.schema.json
analysis-service/contracts/analysis-job-snapshot.schema.json
        ↕
analysis-service/app/models/analysis_contract.py
```

校验器还做两件事：

1. **staleness 检测**：committed manifest/schema 与 Pydantic 实时导出 SHA 不一致则 fail，防止只改 Python 忘改 JSON。
2. **fixture 往返**：`contracts/fixtures/minimal-analysis-result.json` 必须过 `AnalysisResult.model_validate_json`。
