## 1. 要求摘要

每个实机演示面板（`MethodLiveDemo`）底部必须有 **`<details>` 可展开区**。没有溯源区的演示**不得**合并进检测方法模块（计划 §S15）。

须回答读者四个核心疑问：

1. 点按钮后，计算在哪里发生？改输入会不会变？  
2. 这是不是实测图谱 / 是不是 UniDec 本体 / 是不是相似性结论？  
3. 默认数字从哪来（公开库还是合成）？  
4. 能否独立核对（预言机、脚本、仓库路径、外部 URL）？

## 3. 强制小节与内容要点

| 小节 | i18n 键 | 必须回答 |
|---|---|---|
| 这是什么 | `provenanceWhat` | 浏览器内 TS 当场算；改序列/批次/参数会改变输出 |
| 这不是什么 | `provenanceNotWhat` | 非实测 RAW；非 Python 工具进程；非 GxP；非相似性结论 |
| 数据来源 | `provenanceData` | UniProt accession、缓存日期、序列哈希；或合成脚本 + 随机种子 + JSON 路径 |
| 计算原理 | `provenancePrinciple` | 公式步骤，可对框架 `detectionIndicators` / `numericLimit` |
| 独立校验 | `provenanceCheck` | `npm run verify:demo` 或 `verify:method-content` |
| 预言机数值 | `provenanceOracle` | 如 66398.19 Da、99.31%、QR [0.7548, 1.0884] |
| 证据文件 | `provenanceFiles` | `src/lib/live-demo/*.ts`、`tools-poc/scripts/s09*.py`、`output/*.json` |
| 外部链接 | `provenanceLinks` | UniProt、GitHub 仓库、文档 URL（可点击核验） |

数据集中在 `live-demo-provenance.ts`，**新增演示时先写溯源条目再挂组件**（计划明确要求）。

## 4. 三种 demo 的溯源要点（摘要）

### 4.1 `intact-mass`

| 项 | 内容 |
|---|---|
| 数据 | UniProt P02769，REST 下载 2026-08-14；成熟链 25–607 |
| 原理 | 平均残基质量 + 17×(−H) 氧化校正；合成多电荷包络 + 质心去卷积 |
| 预言机 | pyOpenMS 文档级单同位素/平均质量链 → **66398.19 Da** |
| 证据 | `s09a_intact_mass_deconvolution.py`、`output/s09a_intact_mass.json` |

### 4.2 `peptide-map`

| 项 | 内容 |
|---|---|
| 数据 | 同上 BSA 序列；G327A 为演示用单点突变 |
| 原理 | 胰蛋白酶 K/R 切；MS1 前体质量 ± tolerance 匹配理论肽段 |
| 预言机 | s09b **99.31%** 覆盖；G327A 致 3 肽未匹配 |
| 证据 | `s09b_peptide_map_coverage.py`、`output/s09b_peptide_map.json` |

### 4.3 `quality-range`

| 项 | 内容 |
|---|---|
| 数据 | **合成**批次（界面标「合成数据」）；种子与生成逻辑见 s09c JSON |
| 原理 | μR、σR、QR 区间；候选批落入比例 + 均值/SD 比较 |
| 预言机 | QR **[0.7548, 1.0884]**；相似 12/12、偏移 4/12 |
| 证据 | `s09c_free_thiol_quality_range.py`、`output/s09c_free_thiol_quality_range.json` |
| 术语 | 强调 QR ≠ CI ≠ TI（宽度比 1 : 0.156 : 1.206，见 PoC 报告） |

## 5. 与免责声明的关系

`MethodLiveDemo` 顶部仍有短免责声明（`liveDemo.disclaimer`）；展开区提供**可核对的长说明**。两层分工：

- 短声明：防误读（工具能跑 ≠ 方法验证 ≠ 相似性）  
- 展开区：供审计/复现路径（文件、命令、预言机）

S16 后短声明不再提「原理待嵌入」，因原理已移至上方 `MethodContentPanel`。

## 6. 后续大类 checklist

新增演示时必须：

1. 在 `live-demos.ts` 注册 method id → kind（或新 kind）；  
2. 在 `live-demo-provenance.ts` 写满七节内容；  
3. 在 `verify_live_demo.mjs` 或新脚本中加预言机（若有数值）；  
4. 确认 `MethodLiveDemo` 已挂 `LiveDemoProvenancePanel`；  
5. 计划进度日志写 Done。
