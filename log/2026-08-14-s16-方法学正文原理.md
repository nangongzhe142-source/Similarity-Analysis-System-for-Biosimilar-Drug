## 1. 背景与动机

S14–S15 解决的是「演示能当场算、且有溯源」；读者仍不知道**该方法在测什么、输出如何与框架里的检测指标和判定原则挂钩**。方法学正文（`DetectionMethodContent`）在 README 中原本设计为六个字段：

```text
principle, samplePreparation, instrumentParameters,
systemSuitability, dataInterpretation, similarityAssessmentLink
```

本轮**只填 `principle`**，原因：

1. 原理不依赖具体品种和厂商仪器型号，可以在不编造设定值的前提下写实；
2. 样品制备、仪器参数若硬写具体数值，会变成**没有出处的伪 SOP**，比留白更危险；
3. 与框架 Excel 里已有的 `judgingPrinciple`、`numericLimit`、`detectionIndicators` 对齐，原理承担「方法学解释层」，不重复表格字段。

数据与 Excel 生成文件**解耦**：正文放在 sidecar `src/data/method-content.ts`，按 `DetectionMethod.id` 索引；`characterization-items.ts` **不手改**，`contentPlaceholder: true` 保留。

## 3. 原理文本组织（23 段模板 → 33 条方法）

`method-content.ts` 用 `assign(byMethodId, methodIds[], principle)` 批量挂载。共用模板与独占如下：

| 模板 ID | 共用方法数 | 适用场景 |
|---|---|---|
| `PEPTIDE_MAP_LCMSMS` | 6 | 5 条「肽图 LC-MS/MS」正交 + `msms-sequence-coverage-primary-1` |
| 完整/脱糖/亚基相互印证 | 5 | 各质量项的 `*-orthogonal-2` |
| CE-SDS 还原/非还原 | 2 | `free-thiol-orthogonal-2`、`disulfide-bonds-orthogonal-2` |
| 独占段落 | 20 | 各 primary-1、MS1/MSMS/CDR/Edman/二硫键等 |

**每条原理必须覆盖的六点**（计划 §S16 表格）：

1. **测什么** — 物理/化学量 ↔ 分子属性  
2. **怎么测** — 分离/反应/检测链条，**不写**具体仪器设定值  
3. **读什么** — 与框架 `detectionIndicators` 对应  
4. **怎么判** — 定性图谱比对 **或** 定量 quality range；与 `judgingPrinciple` / `numericLimit` 一致  
5. **方法边界** — 盲区、不能单独下结论（例：MS1 ≠ MS/MS 序列确认）  
6. **适用性** — 抗体专属项写明非抗体不适用  

**术语红线**（写入时已遵守）：

| 主题 | 禁止 / 必须 |
|---|---|
| 完整质量 | 不得写「相差 X Da 即相似」 |
| 游离巯基 | QR = (μR − X·σR, μR + X·σR)；不与 CI、TI 混用 |
| 二硫键 | 定性图谱比对；不写数值限度 |
| CDR | 定性身份确认；非抗体不适用 |
| 参照用语 | 参照药 / 参考案例 / 对照品 不混用 |

## 5. UI 行为与组件职责

### 5.1 渲染顺序（`MethodSelector`）

```text
[方法标签按钮组]
    ↓ 若 getMethodContent(id) 有值
MethodContentPanel          ← 白底实线框，「方法学正文 / 原理」
    ↓ 若 getLiveDemoKind(id) 有值
MethodLiveDemo              ← 绿边「实机演示」+ 溯源 <details>
    ↓ 若两者皆无
MethodContentPlaceholder    ← 虚线「检测内容待嵌入」
    ↓ 始终
MethodToolPanel             ← 开源工具与部署实录（S11）
```

### 5.2 `MethodContentPanel` 逻辑

- 有 `principle` 时展示正文；随站点语言切换 `zh` / `en`；
- 五个可选 SOP 字段：**当前全部 undefined** → 底部虚线标签列出「样品制备、仪器参数、系统适用性、数据解读、与相似性评价的衔接」；
- 将来某字段有值时，同一组件会自动从「待嵌入标签」变为「已嵌入段落」，无需改布局；
- 底部固定免责声明（`methodContent.disclaimer`）。

### 5.3 相对 S15 的文案调整

| 键 | 调整 |
|---|---|
| `liveDemo.disclaimer` | 去掉「方法原理仍待嵌入」 |
| `liveDemo.sopStillPending` | 改为「上方已给原理；前处理/仪器参数等待嵌入」 |

## 7. 机械校验 `verify_method_content.mjs`

**命令**：`npm run verify:method-content`（已接入 `npm run check`）

| 规则 | 说明 |
|---|---|
| R1 | `method-content.ts` 中引用的每个 method id 必须在 `characterization-items.ts` 中存在 |
| R2 | **大类全覆盖**：某 `category` 下只要有一条方法有原理，该 category **全部**方法必须有原理 |
| R3 | 每条中文 `principle` 长度 ≥ 60 字符（防 stub 占位） |
| R4 | 只解析 sidecar，不执行 TypeScript |

**2026-08-14 输出**：

```text
methods total        : 184
methods with body    : 33
categories covered   : primary-structure
failures             : 0
```

**脚本刻意不检查**：科学正确性、英文翻译质量、与 PoC 输出的一致性。
